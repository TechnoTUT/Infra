## NDIとは
NDI (Network Device Interface) は、映像と音声をIPネットワーク上で伝送するためのプロトコルです。
- 低遅延で伝送できる
- LANケーブルとスイッチで長距離を伝送できる (HDMIでは長くても15~20m程度)
- 1つの映像を、複数の機器で同時に受信できる
- 1台のコンピュータから、複数の映像を同時に送信・受信できる

## キャプチャーボードとの違い
キャプチャーボードは、1チャネルの映像をUSB経由で1台のパソコンに取り込みます。NDIでは、1本のLANケーブルで、帯域の許す範囲で複数チャネルの映像を送受信できます。よって、LANケーブルだけで、複数のカメラの映像を1台のコンピュータで同時に受信したり、1台のコンピュータ内の複数のアプリケーションの映像を他のパソコンで受信したりできます。

## NDIを利用する

### 接続するネットワーク
NDIを使う機器は、AVネットワーク ([VLAN 20](/network/vlan), `10.10.16.0/20`) に接続します。IPアドレスはDHCPで自動的に設定されます。

### 必要なもの
- カテゴリー5e以上のLANケーブル
- Gigabit Ethernet以上のスイッチ
- NDI対応のソフトウェア (OBS Studio, Resolume Avenue など)

<Admonition type="info">

- **帯域**: 1本の映像が使う帯域には上限があり、送受信できる本数はリンクの帯域で決まります。目安として、1080p60のNDI (フル帯域) は1本あたり約125~150Mbpsを使うため、Gigabit Ethernetではおおよそ6本までです。帯域が不足すると、映像が途切れたりコマ落ちしたりします。
- **スイッチの性能**: 全てのポートが同時に最大速度で通信できる (ノンブロッキングの) スイッチを使ってください。スイッチ全体の処理能力 (スイッチングファブリック) が低いと、ポートの速度が足りていても帯域が不足します。
- **機器の検出**: NDIは、mDNS (マルチキャスト `224.0.0.251`) で同じセグメント内の機器を検出します。mDNSはルータを越えないため、[NDI Discovery Server](#ndi-discovery-server) を使わない場合、送信側と受信側は同じVLANに接続する必要があります。
- **マルチキャスト送信**: 映像をマルチキャストで送信する場合は、IGMPスヌーピングのQuerierがVLAN内に必要です。TechnoTUT NetworkのAVネットワーク (VLAN 20) では、コアスイッチ (N-1) がQuerierです。
- **ファイアウォール**: NDIでは、コンピュータ同士が直接通信して映像を送受信します。コンピュータのファイアウォールで通信がブロックされていると機能しません。Windowsの場合は、接続しているネットワークがプライベートネットワークに設定されているか確認します。

</Admonition>

### utone-linuxの場合
utone-linuxは、標準でNDIの送受信機能を搭載しています。またLive環境で動作するため、OSのインストールは不要です。\
キャプチャーボードと組み合わせて HDMI → NDI、ディスプレイと組み合わせて NDI → HDMI の変換ができます。使用方法は [utone-linux](/service/utone-linux) を参照してください。

### Resolume Avenueの場合
Resolume Avenueは、標準でNDIの送受信ができます。
- **送信**: `Output` メニューからNDIを有効にすると、メイン出力がNDIで送信されます。
- **受信**: ネットワーク上のNDIソースは、`Sources` タブに表示されます。

詳細は、[Resolume AvenueのNDIについて](https://resolume.com/support/ja/NDI_inputs_and_outputs)を参照してください。

### OBS Studioの場合
OBS Studioでは、プラグインの[DistroAV](https://github.com/DistroAV/DistroAV)をインストールすると、NDIの送受信ができます。OBSのバージョンと環境に合ったものをダウンロードしてください。\
動作しない場合、NDIのランタイムがインストールされていない可能性があります。インストール方法は以下をご覧ください。\
https://github.com/DistroAV/DistroAV/wiki/1.-Installation

Ubuntuの場合は、[TechnoTUT/OBS-Temprate](https://github.com/TechnoTUT/OBS-Temprate) のスクリプトで必要なものを一括でインストールできます。
```bash
curl https://raw.githubusercontent.com/TechnoTUT/OBS-Temprate/refs/heads/main/install.sh | bash
```

<Admonition type="info">

このスクリプトは、以下を行います。既存の環境に実行する場合は注意してください。
- PPA (`ppa:ubuntuhandbook1/ffmpeg7`, `ppa:obsproject/obs-studio`) の追加
- FFmpeg、OBS Studio、DistroAV、NDIランタイムのインストール
- `~/.ndi/ndi-config.v1.json` の上書き (NDI Discovery Serverの設定)

</Admonition>

#### 送信
OBS Studioを起動し、`Tools` > `DistroAV NDI Settings` を選択し、`Main Output` を有効にします。

#### 受信
OBS Studioを起動し、ソースの追加から `NDI Source` を選択し、`Source name` で受信したいソースを選びます。`Latency Mode` は `Lowest (unbuffered)` を選択します。

## NDI Discovery Server
NDI Discovery Serverは、NDIのソースを登録・検索するためのサーバです。送信側は自分のソースをDiscovery Serverに登録し、受信側はDiscovery Serverにソースの一覧を問い合わせます。mDNSの代わりに使うため、マルチキャストが届かない環境でも機器を検出できます。

TechnoTUT Networkでは、コンテナ基盤上でNDI Discovery Serverを提供しています。\
[![TechnoTUT/ndi-discovery-server - GitHub](https://gh-card.dev/repos/TechnoTUT/ndi-discovery-server.svg?fullname=)](https://github.com/TechnoTUT/ndi-discovery-server/pkgs/container/ndi-discovery-server)

| 項目 | 値 |
| :--- | :--- |
| アドレス | `10.12.230.254` (`ndi.svc.technotut.net`) |
| ポート | TCP 5959 |
| 利用できるVLAN | AV (VLAN 20) のみ (FortiGateのポリシー `al-av-sv` で許可) |

<Admonition type="info">

現在のTechnoTUT Networkでは、VLANをまたいだNDIの送受信はできません。

- Discovery Serverに接続できるのは、AV (VLAN 20) からだけです。
- AVへの通信がFortiGateで許可されているのは、DJ (VLAN 10) とPA (VLAN 40) からだけです。DJとPAからはDiscovery Serverに接続できません。

VLANをまたいでNDIを使うには、Discovery Serverへの通信と、送信側・受信側の間の通信の両方を、FortiGateで許可する必要があります。詳細は [ネットワーク仕様](/network/spec#通信制御) を参照してください。

</Admonition>

### 各機器への設定

#### utone-linuxの場合
utone-linuxでは、予めNDI Discovery ServerのIPアドレスが設定されています。設定は不要です。

#### Windows/Macの場合
[NDI Tools](https://ndi.video/tools/)をインストールし、`NDI Access Manager` を起動します。`Advanced` タブの `Discovery Server` に `10.12.230.254` を入力して保存します。

#### Linuxの場合
`~/.ndi/ndi-config.v1.json` を作成し、`networks.discovery` にDiscovery Serverのアドレスを設定します。\
https://docs.ndi.video/all/getting-started/white-paper/discovery-and-registration/discovery-server
```json
{
  "ndi" : {
    "networks" : {
      "ips" : "",
      "discovery" : "10.12.230.254"
    }
  }
}
```

utone-linuxでは、上記に加えて次の項目も設定しています。

| 項目 | 値 | 意味 |
| :--- | :--- | :--- |
| `rudp.recv.enable` | `true` | UDP (Reliable UDP) で受信する |
| `tcp.recv.enable` | `false` | TCPでは受信しない |
| `unicast.recv.enable` | `true` | ユニキャストで受信する |
| `multicast.send` | 有効、`239.255.0.0/16` | マルチキャストで送信する。VLAN内にIGMPスヌーピングのQuerierが必要 |
| `groups.send` / `groups.recv` | `public` | 送受信するグループ |

## トラブルシューティング
以下のページを参考にしてください。
- [2. Troubleshooting | DistroAV/DistroAV Wiki](https://github.com/DistroAV/DistroAV/wiki/2.-Troubleshooting)

Ubuntuでufwを利用している場合、以下のコマンドでNDIの通信を許可します。

<Admonition type="info">

ufwを有効にすると、許可していない通信は全て遮断されます。SSHで接続している場合は、先に `sudo ufw allow ssh` でSSHを許可してください。

</Admonition>

```bash
sudo ufw allow 5353/udp       # mDNS
sudo ufw allow 5959:5969/tcp  # Discovery, 映像の送受信
sudo ufw allow 5959:5969/udp
sudo ufw allow 6960:6970/tcp
sudo ufw allow 6960:6970/udp
sudo ufw allow 7960:7970/tcp
sudo ufw allow 7960:7970/udp
sudo ufw enable
sudo ufw status
```
