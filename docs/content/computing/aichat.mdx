## 概要
[AI チャット](/service/aichat) (aichat) は、Gemini の function calling で、クラスタとリポジトリを読んで答える Web チャットです。

| 項目 | 内容 |
|---|---|
| ソース | [TechnoTUT/infra-assistant](https://github.com/TechnoTUT/infra-assistant) (Python、FastAPI、google-genai。依存は uv で管理) |
| イメージ | `ghcr.io/technotut/infra-assistant:main` (infra-assistant リポジトリの GitHub Actions がビルド) |
| マニフェスト | [`k8s/manifest/aichat/`](https://github.com/TechnoTUT/Infra/tree/main/k8s/manifest/aichat) (Argo CD の Application `aichat`) |
| モデル | `gemini-3.8-flash` (Gemini API)。Deployment の環境変数 `GEMINI_MODEL` で変える。1 問でツールを呼ぶたびに 1 リクエストを使うので、RPD の少ないモデルは避ける |
| URL | http://ai.svc.technotut.net (Cilium Ingress。VLAN 10・20 から HTTP を許可) |
| 問題の報告 | 調べて問題が見つかると、ツール `report_issue` が Discord の Webhook に送る。URL は Ansible Vault の `vault_discord_webhook_url` (任意) に保管し、Secret `aichat` のキー `discord-webhook-url` に入れる |
| API キー | Ansible の `aichat.yml` が Secret `aichat` を作成。Ansible Vault の `vault_gemini_api_key` に保管 |

## 仕組み
1. ブラウザが質問と、それまでのやりとりを `POST /api/chat` に送ります。サーバーはジョブを作って ID を返します。
2. サーバーは Gemini に質問とツールの一覧を渡します。Gemini がツールを呼ぶと、サーバーが実行して結果を返します。これを答えが出るまで (最大 10 回) 繰り返します。
3. ブラウザは `GET /api/jobs/<ID>` を 1 秒ごとに読み、ツールの呼び出しと答えを表示します。

ジョブとポーリングにしているのは、Cilium Ingress (Envoy) のルートが 15 秒で切れるためです。ツールを何回も呼ぶ質問は 15 秒を超えます。\
ジョブはメモリに持つので、レプリカは 1 つです。会話の履歴はブラウザが持ち、サーバーには残りません。

### ツール
| ツール | 内容 |
|---|---|
| `cluster_overview` | ノード、問題のある Pod、Argo CD のアプリの状態 |
| `list_resources` / `get_resource` | `kubectl get` / `kubectl get -o yaml` 相当 |
| `get_pod_logs` | `kubectl logs` 相当 (最大 300 行) |
| `get_events` | `kubectl get events` 相当 |
| `ping` / `dns_lookup` / `tcp_check` / `http_check` | Pod から宛先への ping、DNS (nslookup 相当)、TCP 接続、HTTP の状態を調べる (Pod から見た結果) |
| `vlan_probe` | VLAN 10・20 の側から ping / arping / traceroute / DNS / TCP / HTTP を出す。必要になったとき、検証用の Pod (netprobe) をその VLAN に VXLAN でつないで起動し、使い終わって 5 分で消す |
| `list_repo_files` / `read_repo_file` / `search_repo` | git-sync が取り込んだリポジトリを読む |

リポジトリは、サイドカーの git-sync が TechnoTUT/Infra の main を 5 分ごとに取り込みます。

## 安全のための制限
- ServiceAccount `aichat` の ClusterRole `aichat-readonly` は、種類を列挙した `get` / `list` / `watch` だけです。Secret、`pods/exec`、書き込みの verb は含みません (書き込みは次の項目)。
- 書き込みは、画面の確認ボタンで承認した操作だけです。ClusterRole `aichat-operator` (Pod の `delete`、Deployment・StatefulSet・DaemonSet の `patch`、Job の `create`) と、argocd の Role (Application の `patch`) を、アプリの namespace (cam1、cam2、dmxctl、dmxsim、live、ndi、plmux、speedtest、time) にだけ RoleBinding で与えます。kube-system、argocd のほかのリソース、cilium、arc-*、external-dns、registry、fortigate-operator、aichat 自身は対象外です。マニフェストは [`k8s/manifest/aichat-rbac/`](https://github.com/TechnoTUT/Infra/tree/main/k8s/manifest/aichat-rbac) (Argo CD の Application `aichat-rbac`) にあります。
- アプリでも、読める種類を `app/tools.py` の `KINDS` に限っています。種類を足すときは、ClusterRole と `KINDS` の両方に足します。
- リポジトリの `vault.yml`、`.git`、鍵らしいファイル (`*.key`、`*.pem`) は読みません。
- Gemini API の無料枠のため、送った内容は Google のサービス改善に使われることがあります。Secret を読めないようにしているのはこのためでもあります。ただし Pod のログはそのまま送るので、ログに秘密を出すアプリには注意します。
- ネットワーク診断は、ループバックとリンクローカル (クラウドのメタデータなど) には送りません。TCP と HTTP は決まったポートだけ、HTTP は本文を読まず状態とヘッダーだけ、全体で 1 分に 30 回までです。ping は特権なしの ICMP (Pod の `net.ipv4.ping_group_range` で許可されている必要がある) を使います。
- `vlan_probe` の Pod は、aichat が `netprobe` 名前空間に作ります。aichat に与える権限はその名前空間の Pod の get / list / create / delete だけで、Pod の仕様 (イメージ、NET_RAW と NET_ADMIN だけの capability、root、ReadOnly のファイルシステム) は aichat のコードに固定です。AI が選べるのは VLAN だけです。同時に 2 つまで (ResourceQuota)、15 分で自動停止 (`activeDeadlineSeconds`)、API (8080) には aichat からだけつなげます (NetworkPolicy)。ソースは infra-assistant の `netprobe/`、マニフェストは [`k8s/manifest/netprobe/`](https://github.com/TechnoTUT/Infra/tree/main/k8s/manifest/netprobe) です。対象の VLAN は、`vxlan_cni_allowed_vlans` と `app/netdiag.py` の `NETPROBE_VLANS` の両方に足します。
- Discord への報告は、10 分に 5 件まで、同じ題名は 30 分は再送せず、メンションは無効、秘密らしい文字列は伏せて送ります。画面にログインがないので、誰かの質問で報告が送られることがあります。
- 画面にログインはありません。VLAN 10・20 の誰でも使えます。同時に動かす質問は 2 つまで (`MAX_CONCURRENT`) です。

## 導入
1. [Google AI Studio](https://aistudio.google.com/apikey) で API キーを発行します (無料枠)。
2. Ansible Vault に入れて、Secret を作ります。
   ```bash
   cd k8s/ansible
   ansible-vault edit inventory/group_vars/all/vault.yml   # vault_gemini_api_key: "<キー>" を足す
   ansible becky -m ansible.builtin.include_role -a "name=addons tasks_from=aichat"   # main のクラスタだけ
   ```
3. main にマージすると、Argo CD がアプリをデプロイします。Secret を後から作ったときは、Pod を作り直します (`kubectl -n aichat rollout restart deploy/aichat`)。

ghcr.io のパッケージ `infra-assistant` が非公開だと、イメージを pull できません。初回のビルド後、パッケージの設定で公開 (Public) にします。

## 手元で動かす
```bash
git clone https://github.com/TechnoTUT/infra-assistant
cd infra-assistant
uv sync
GEMINI_API_KEY=<キー> REPO_DIR=<Infra の clone> uv run uvicorn app.main:app --reload
```
クラスタには手元の kubeconfig で接続します。http://localhost:8000 を開きます。
